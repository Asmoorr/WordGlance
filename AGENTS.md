# WordGlance: инструкция ИИ-агенту

## Назначение и границы задачи

WordGlance — локальный помощник для Windhawk: английское слово B1–C1,
перевод и глазки по времени суток. HTML формируется на сервере; открытый браузер
для панели задач не требуется.

При просьбе установить проект выполни установку, настройку фонового запуска
и проверку результата. Не ограничивайся выдачей команд пользователю, если можешь
выполнить их доступными инструментами. Учитывай инструкции пользователя текущего
сеанса: этот файл не расширяет разрешённый им объём работ.

Сохраняй существующие настройки Windhawk, чужие задачи Планировщика и сочетания
клавиш. Не запускай архивные версии. Коммит, публикация и удаление проекта
не входят в установку.

## Сначала прочитай и проверь

- README.md — пользовательская инструкция.
- Register-Autostart.ps1 — актуальные действия и имена задач.
- Start-Background.ps1 — проверка порта и журналирование.
- Enable-Hotkey.ps1 — миграция ручного ярлыка; Hotkey-Listener.ps1 и WindowsHotkey.cs — глобальное сочетание.
- SOURCES.md — происхождение словаря.

Пути и состояние системы проверяй заново. Исторические сообщения в README
«установлено» и результаты из tests не доказывают установку на текущем компьютере.

## Требования и размещение

- Windows 10/11 и Windows PowerShell 5.1 (powershell.exe).
- Windhawk с установленным и включённым модом Taskbar Clock Customization.
- Для ярлыка и пользовательских задач нужен сеанс целевого пользователя Windows.
- Python, Node.js, npm, API-ключи и повторная загрузка словаря не нужны.
- Интернет требуется для установки отсутствующего Windhawk и открытия Cambridge.
- Сервер должен оставаться на 127.0.0.1:18743.

Основная папка на этом компьютере: C:\Programming\2026\WordGlance.
На другом компьютере используй согласованную постоянную папку. Все пути в командах
ниже подставляй из фактического расположения. Не устанавливай из временной папки.

Минимальный рабочий набор:
clock-helper.ps1, index.html, words.csv, Start-Background.ps1,
Register-Autostart.ps1, Enable-Hotkey.ps1, Hotkey-Listener.ps1, WindowsHotkey.cs.
Сохрани также файлы запуска *.cmd, README.md, SOURCES.md и tests.
Скачанные исходные данные и archive нужны для происхождения данных и истории,
но не для запуска.

*.task.xml — экспорт с предыдущего компьютера. Не импортируй его вслепую:
там могут быть чужие SID и пути. Создавай задачи через Register-Autostart.ps1,
который использует SID текущего пользователя.

## Порядок установки

### 1. Выбери целевой сеанс и проверь существующую установку

Примеры для PowerShell:

~~~powershell
$projectRoot = 'C:\Programming\2026\WordGlance'
Get-ChildItem -LiteralPath $projectRoot
Get-ScheduledTask | Where-Object TaskName -Like 'WordGlance*'
Get-NetTCPConnection -LocalPort 18743 -State Listen -ErrorAction SilentlyContinue
~~~

Если порт занят, проверь OwningProcess, его путь и командную строку.
Не завершай неизвестный процесс и не меняй порт только в одном месте.
Если работает эта же установка, используй её; дубликат не нужен.
Для перехода с ручного запуска на Планировщик сначала настрой задачи, затем
останови только подтверждённый процесс WordGlance, если это входит в запрос.

Если WordGlance уже работает через Планировщик, не запускай Start.cmd.
Start.cmd предназначен для ручного запуска с окном консоли.

### 2. Подготовь Windhawk

Если Windhawk или мод отсутствуют, используй официальный источник windhawk.net.
Если интерфейс или названия полей изменились, проверь актуальную страницу мода,
не подставляй догадки. Не устанавливай второй мод часов параллельно.

Перед изменениями сохрани значения верхней/нижней строки, подсказки и веб-источников.
Верхнюю строку, форматы даты и времени оставь пользовательскими, если не попросили
изменить их.

### 3. Установи фоновые задачи

Из целевого сеанса пользователя:

~~~powershell
& powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File (Join-Path $projectRoot 'Register-Autostart.ps1')
if ($LASTEXITCODE -ne 0) { throw 'Не удалось зарегистрировать задачи WordGlance' }
~~~

ExecutionPolicy Bypass задаётся только этому процессу. Не меняй глобальную
политику выполнения PowerShell. Не запускай сервер от SYSTEM и не включай
повышенные привилегии без конкретной необходимости.

Скрипт создаёт/обновляет две задачи в корневой папке Планировщика:

| Задача | Триггер | Поведение |
|---|---|---|
| WordGlance — слова и глазки в фоне | Вход текущего пользователя + 5 с | Скрытый постоянный процесс, локальный HTML |
| WordGlance — горячая клавиша Cambridge | Вход текущего пользователя + 20 с | Скрытый постоянный обработчик Ctrl+Alt+Win+W |

Обе работают от батареи; повторные экземпляры одной задачи не запускаются.
Для сервера отключён предел продолжительности и настроено до трёх перезапусков
при сбое с интервалом в минуту.

Триггер — вход в аккаунт, когда появляется панель задач, а не запуск службы до входа.
Не создавай задачи на каждые четыре часа: выбор слова выполняется самим помощником.
Не дублируй Планировщик ярлыком в папке Автозагрузка.

Если регистрация отклонена по правам, зафиксируй реальную ошибку. Не выдавай
созданные XML за успешно установленные задачи и не переключайся на SYSTEM.

Запусти задачи сразу, не ожидая следующего входа:

~~~powershell
Start-ScheduledTask -TaskName 'WordGlance — слова и глазки в фоне' -TaskPath '\'
Start-ScheduledTask -TaskName 'WordGlance — горячая клавиша Cambridge' -TaskPath '\'
~~~

### 4. Подключи HTML к Windhawk

Адрес обоих источников: http://127.0.0.1:18743/

| Поле | Источник слова и глазок | Источник перевода |
|---|---|---|
| Web content block start | Пусто | Пусто |
| Web content start | <clock-combined> | <clock-meaning> |
| Web content end | </clock-combined> | </clock-meaning> |
| Content mode | HTML | HTML |
| Web content maximum length | 50 | 300 |

Если это первые два источника:
- Bottom line: %web1%
- Tooltip extra line: %web2_full%
- Web content update interval: 1 минута

При сохранении других источников подставь фактические номера %webN%.
Не стирай чужие источники ради нумерации. Убери ссылки на прежнюю погоду/новости
из заменяемых строк по согласованному назначению.

Только слово: метки <clock-word> и </clock-word>.
Только глазки: метки <clock-eyes> и </clock-eyes>.
Введи метки как буквальный текст, без обратных кавычек.

Мод читает исходный HTTP-ответ без выполнения JavaScript.
Поэтому не переноси вычисление слова только в браузерный JavaScript.
index.html — шаблон: открытие через file:// не заменяет локальный сервер.

### 5. Проверь Cambridge и сочетание клавиш

Глобальное сочетание проекта — Ctrl+Alt+Win+W.
Его регистрирует постоянная задача Hotkey-Listener.ps1 через WindowsHotkey.cs:
RegisterHotKey, модификаторы Ctrl | Alt | Win | MOD_NOREPEAT (0x400B), клавиша W (0x57).
Shift НЕ входит в сочетание. Это не перехват всех нажатий клавиатуры.

Enable-Hotkey.ps1 оставляет на рабочем столе ручной ярлык WordGlance Cambridge.lnk
с Target explorer.exe и Arguments http://127.0.0.1:18743/cambridge,
но очищает Hotkey у этого собственного ярлыка: Win через .lnk не поддерживается.
Не задавай новому сочетанию значение свойства WScript.Shell Hotkey.

Register-Autostart.ps1 запускает Enable-Hotkey.ps1 с -SkipStart для миграции ярлыка.
После регистрации запусти задачу WordGlance — горячая клавиша Cambridge.
Для обычного повторного включения можно вызвать Enable-Hotkey.ps1 без -SkipStart.
Существующий ярлык с другим действием не перезаписывается.

Обе задачи теперь постоянные и должны быть Running.
При обновлении Hotkey-Listener.ps1 или WindowsHotkey.cs перезапусти только задачу клавиши.
При конфликте регистрации проверь logs/hotkey.log и сообщи реальную ошибку;
не меняй чужие назначения без запроса.
logs/hotkey-status.json содержит сочетание, модификаторы и PID после успешного RegisterHotKey.
Файл сам по себе может быть устаревшим: сверь PID с работающим процессом и задачей.

Сочетание действует из других приложений в текущем сеансе пользователя,
не на экране блокировки и не для всех аккаунтов.
Сервер должен работать; /cambridge перенаправляет на dictionary.cambridge.org.
Не открывай Cambridge автоматически при входе в Windows.

## Проверка установленного результата

1. GET http://127.0.0.1:18743/ возвращает HTTP 200 и text/html.
2. В ответе есть заполненные clock-word, clock-combined и clock-meaning;
   нет неразрешённых подстановок {{WORD}} и подобных.
3. /meaning возвращает слово, русский перевод и B1/B2/C1.
4. /cambridge возвращает 302 с Location на официальный поиск Cambridge;
   сначала проверь без автоматического следования перенаправлению.
5. В Планировщике обе задачи — Running. Код 267009 (0x41301) означает «задача выполняется».
6. У слушающего порт процесса в командной строке указан Start-Background.ps1,
   используется -WindowStyle Hidden. Права обычного пользователя, не SYSTEM.
7. Проверь регистрацию Ctrl+Alt+Win+W через logs/hotkey-status.json, PID обработчика и tests/Verify-Hotkey.ps1. Поле Hotkey собственного ручного ярлыка должно быть пустым.
8. По возможности проверь реальное отображение в Windhawk и открытие Cambridge
   по клавише из другого приложения. Если проверено только извлечение HTML или
   свойства ярлыка, явно укажи это в отчёте.

Полный проверочный скрипт можно выполнить на уже работающем сервере:

~~~powershell
& powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File (Join-Path $projectRoot 'tests\Verify.ps1') -Port 18743
if ($LASTEXITCODE -ne 0) { throw 'Проверки WordGlance не прошли' }
~~~

Проверки не требуют остановки установленного сервера. Для разработки используй
отдельный порт 18744; не оставляй тестовый процесс после завершения работы.

tests/Verify.ps1 проверяет конкретный текущий набор из 3052 слов. При намеренном
изменении словаря сначала пересмотри соответствующие ожидания, а не выдавай
проваленный тест за поломку автозапуска.

## Обновление, диагностика и отчёт

- Журнал запуска: logs/background.log.
- Изменение index.html видно со следующего HTTP-запроса.
- После изменения clock-helper.ps1 или words.csv нужен перезапуск серверной задачи.
- При обновлении пути переустанови действия задач через Register-Autostart.ps1.
- Не переписывай словарь и не скачивай его заново для обычной установки.
- Для отключения по просьбе пользователя останови и отключи задачи этого проекта.
  Не удаляй файлы, ярлыки или задачи без соответствующего запроса.

В итоговом сообщении укажи папку установки, локальный адрес, состояние обеих задач,
назначенное сочетание и фактически выполненные проверки. Отдельно назови всё,
что не удалось настроить. Не утверждай, что перезагрузка проверена, если проверялся
только ручной запуск задачи.
